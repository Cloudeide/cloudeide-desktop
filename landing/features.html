Plans before it builds

For bigger jobs the agent works out what it needs to know before it writes any code.

  • Asks first. When there is a real choice to make, it asks, with options to pick from, and waits for your answer.
  • A plan you can see. It writes the steps as a to-do list in the chat and ticks each one off as it goes.
  • Small jobs stay small. A one-line fix gets no plan and no questions. It just does it.

Works across your codebase

Open a folder, open Chat, and say what you want. The agent works on your real project, in your editor, and changes every file the job touches.

  • Reads first. It lists the project, searches it, finds symbols and their uses, and reads the files that matter before it changes anything.
  • Edits across files. Changes are made in the editor, marked line by line, in as many files as the job needs.
  • Understands pictures. Attach a screenshot and it sees it. Attach files, folders or a selection with #.
  • Agent and Ask. Agent mode changes code. Ask mode only reads and answers.
  • Sessions. Every conversation is kept in the sessions list, with what it changed.
  • Your tools. MCP servers you add in VS Code are offered to the agent. Switch off any tool you don't want it to use.

Review every change

Nothing the agent writes stays until you say so.

  • Every change shows in place in the editor: new lines green, removed lines red.
  • Keep or Undo each change, each file, or everything at once.
  • Checkpoints let you go back to how things were before any request.

Checks its own work

The agent does not hand back work it has not checked.

  • Problems first. After editing, it asks the editor for errors in the files it changed and fixes them.
  • Runs your tests. It runs them in the terminal, where you can watch.
  • Fixes what fails. When a test fails it reads why, fixes the cause, and runs the tests again.
  • Says what it ran. Its last message tells you what it checked and what passed.

Tab

Grey suggestions as you type, that follow your team's rules. Press Tab to accept. Finish a function and it offers to write the test for it.

Pull requests

Type /pr in Chat. Unsaved files are saved, and a branch, a commit and a pull request are made for you. You confirm before anything is pushed.

Team rules

  • An admin writes the rules once, for the whole organisation. Every agent and every suggestion follows them.
  • A project can add its own in AGENTS.md at the root of the folder.

Ships it, too

Ask the agent to put it online, from the same window. No other platform needed.

  • Preview first. It builds the project and publishes a preview on its own HTTPS address, then checks the page loads before telling you it's live.
  • Production when you allow it. Going to production always asks you first.
  • Fixes a failed build. If a build fails, it reads the log, fixes the cause and tries again, then stops and tells you if it can't.
  • Roll back any time. Every deploy is kept. Go back to an earlier one, or stop one that is still building, from the Cloud tab.
  • Your domain. Add your own domain, copy the DNS record, and it is checked for you. Environment variables keep secret values hidden.
  • Static sites today. React, Vite, Astro, SvelteKit (static), Next.js (static export), Vue, Angular and plain HTML.

Built on VS Code

Your extensions, keybindings and themes work as they do in VS Code. The agent works on the folder you opened; what it reads is sent to the model to answer you, as described in the Data Use Policy.
